# Proposal: Update Insurance Type Upload Logic

## Summary

统一"投保类型"的术语及业务逻辑，根据不同类型的投保业务，动态调整前端上传控件，规范后端文件存储结构，并确保Web端与APP端下载路径的一致性。

## Motivation

当前系统存在以下问题：

1. **术语不一致**: 现有 `NEW`/`RENEWAL` 对应"新保"/"续保"，业务人员反映不够直观
2. **上传控件不动态**: 所有投保类型上传相同的文件，无法根据业务类型区分必填文件
3. **文件类型枚举不完整**: 缺少对行驶证(正/反面)、车船税减免证明、投保人身份证等文件类型的支持
4. **存储路径不规范**: 当前存储路径仅为 `{date}/{transaction_id}/{filename}`，缺少业务类型和文件类型的区分

## User Impact

- **车险业务人员**: 需要根据投保类型上传不同文件，前端应动态显示必填项
- **后台运营**: 需要能查询和统计不同投保类型的业务数据
- **RPA流程**: 需要根据文件类型执行不同的处理逻辑
- **APP端**: 需要与Web端保持一致的存储路径和文件类型规范

## Scope

### In Scope
- 枚举值修改：`NEW` → `NEW_VEHICLE`，`RENEWAL` → `OLD_VEHICLE`
- 新增文件类型枚举值：`DRIVING_LICENSE_FRONT`、`DRIVING_LICENSE_BACK`、`TAX_EXEMPT_CERT`、`INSURER_ID_CARD_FRONT`、`INSURER_ID_CARD_BACK`
- 新增 `holder_phone` (投保人手机号) 字段用于转保场景
- 前端表单：投保类型改为 Radio 单选框，根据选择动态显示必填文件
- 存储路径规则：`{transaction_id}/{file_type}{ext}`
- 后端校验：根据业务类型校验必填文件

### Out of Scope
- 不修改现有RPA流程逻辑
- 不实现文件内容校验(仅校验文件类型和数量)

## Success Criteria

1. 投保类型术语变更为"新车投保"/"旧车投保"，且为单选互斥
2. 不同投保类型显示不同的必填文件清单
3. 免税/转保附加选项显示额外必填文件
4. 转保场景可录入投保人手机号
5. 存储路径包含事务ID和文件类型信息
6. 后端校验必填文件是否齐全

## File Upload Requirements

| 投保类型 | 必填文件 |
|---------|---------|
| 新车投保 | 身份证正面、身份证反面、电子发票、合格证 |
| 旧车投保 | 身份证正面、身份证反面、行驶证正面、行驶证反面 |

| 特殊场景 | 附加必填文件 | 附加录入项 |
|---------|-------------|-----------|
| 免税投保 | 车船税减免税证明 | - |
| 转保 | 投保人身份证正面、投保人身份证反面 | 投保人手机号 |

## Non-Goals

- 不实现文件内容OCR或自动识别
- 不修改现有事务状态机逻辑
- 不实现文件数量超过限制的自动拒绝逻辑
- 不兼容旧数据枚举值(NEW/RENEWAL)
