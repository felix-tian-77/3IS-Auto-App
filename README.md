以下是优化后的保单自动生成（RPA）系统需求规格说明书。优化重点在于解耦业务逻辑、增强系统弹性、明确数据流向，并针对你新增的“手机端App”进行了整合与规范。

一、 系统概述与目标

构建一个分布式、高可用的RPA编排平台，实现车险投保资料的自动化录入与处理。系统需支持新旧保单的智能识别、任务的动态调度、多设备集群管理以及全流程的状态闭环监控。

二、 服务端需求 (Backend System)

1. 事务接入与治理

•   多渠道接入：支持 Web 门户手动提交与 REST API 批量推送。

•   智能业务路由：

    ◦   系统自动判别“新保/续保”类型。

    ◦   根据业务类型动态加载校验规则（Schema Validation），确保影像资料（身份证、行驶证、合格证、发票）齐全且格式合规（PDF/Image）。

•   全生命周期ID管理：生成全局唯一的 Transaction ID，贯穿后续所有服务调用与设备操作。

2. 调度中心 (Dispatcher)

•   智能负载均衡：

    ◦   摒弃简单平均分配，采用最小连接数或权重轮询算法。

    ◦   调度依据：客户端机器性能、当前负载（CPU/内存）、挂载的Android设备空闲率。

•   设备亲和性策略：确保同一事务分配的RPA步骤优先在固定设备上执行，避免跨设备切换导致的上下文丢失。

•   状态机管理：维护事务的强状态流转（PENDING -> DISPATCHED -> DOWNLOADING -> RUNNING -> SUCCESS/FAIL），并记录状态变更时间戳。

3. 资产管理与监控

•   客户端注册中心：管理 Worker 节点的心跳（Heartbeat）、版本号及能力标签（Tag）。

•   设备池管理：维护 Android 设备的唯一标识（SN/UDID）、在线状态、占用情况。

•   审计日志：全量记录事务操作日志、异常堆栈及调度决策日志，用于复盘与合规审查。

三、 客户端需求 (Client Agent / Desktop)

1. 节点管理

•   自动注册：启动时向服务端注册，上报本机指纹及已连接的Android设备列表。

•   状态同步：周期性上报本机及挂载设备的健康度指标（电量、存储空间、是否锁屏）。

2. 任务执行引擎

•   指令监听：支持长轮询或 WebSocket 实时接收服务端下发的任务指令。

•   数据拉取：根据任务指令下载对应的客户元数据（如手机号、事务ID）及影像附件，存储于本地加密沙箱。

•   RPA 编排器 (Orchestrator)：

    ◦   支持多 RPA 流程定义（Flows），每个流程包含多个有序步骤（Steps）。

    ◦   支持步骤级重试机制（Retry Policy）与超时熔断。

•   结果回传：执行完毕后，即时向服务端上报执行结果、截图证据及耗时。

四、 移动端需求 (Mobile Agent / Android)

优化说明：将“下载文件”逻辑从客户端剥离至手机端，形成“客户端控管，手机端执行”的架构，更符合移动端RPA的最佳实践。

1. 原生代理服务 (Native Agent)

•   任务监听：Android App 作为独立Agent，通过 Socket/HTTP 监听来自桌面客户端的指令（或由服务端直连，视网络架构而定）。

•   文件同步：

    ◦   根据事务ID，从服务端下载对应的影像资料（PDF/Images）。

    ◦   支持断点续传与 MD5 校验，确保文件完整性。

    ◦   存储路径支持可配置化管理（Configurable Storage Path）。

•   环境准备：下载完成后，更新服务端状态为“就绪”，并唤醒 RPA 脚本执行环境。

2. 安全与隔离

•   沙箱机制：影像文件仅存储在制定目录，允许外部应用访问。

•   清理策略：事务处理结束（成功或终态失败）后，自动触发文件清理机制，防止隐私数据滞留。

五、 技术架构约束 (Architecture Constraints)

层级 技术选型与规范

核心语言 Python (>=3.14)，严格使用 UV 进行依赖管理与虚拟环境隔离，确保构建一致性。

自动化层 Airtest 作为核心图像识别与设备控制框架；封装统一的 Device Controller 接口，屏蔽 Android 设备差异。

通信协议 前后端及移动端通信均采用 HTTPS/TLS 加密，API 需携带 Token 鉴权。

配置管理 客户端与移动端配置（如服务器地址、存储路径）需支持 YAML/JSON 文件配置，禁止硬编码。

六、 非功能性需求 (NFRs)
维度 需求描述

可观测性 需提供 Dashboard，展示：事务积压量、设备在线率、脚本成功率、平均执行时长 (ATT)。

容错性 支持“死信队列”(Dead Letter Queue)，处理连续失败的事务；支持客户端崩溃自恢复。

扩展性 支持横向扩展 Worker 节点；支持未来接入 iOS 设备或新的保险产品流程。

安全性 敏感信息（手机号、身份证号）在传输和存储时需脱敏或加密；API 防刷限流。
