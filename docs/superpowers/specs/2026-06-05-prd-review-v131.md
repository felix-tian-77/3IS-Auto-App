## B. V1.3.1 引入的新不一致（4 处）

V1.3.1 在闭环 V1.3 前提时引入了 4 处新的内部不一致。这是 V1.3 时代没有的。

### B-1. customer_id 路径不一致（高优先级，需立即修复）

**问题描述**：
- §5.2 Attachment（V1.3.1 加 customer_id）实际路径：`local://attachments/{customer_id}/ATT-xxx/idcard.jpg`
- §7.11 多租户隔离（V1.3.1）执行路径：`/data/attachments/{customer_id}/{attachment_id}/{filename}`
- §AC-NEW-V13-002 验收（line 2319）**仍用 V1.3 旧路径**：`/data/attachments/{attachment_id}/{filename}`（缺 customer_id）
- 术语表 §LocalStorageBackend（line 163）**仍写 V1.3 旧路径**：`默认路径 /data/attachments/{attachment_id}/{filename}`

**影响**：实施团队读 AC-NEW-V13-002 时会按"无 customer_id"实现，破坏 §7.11 多租户隔离。

**修复建议**：V1.3.1 patch (V1.3.1.1 或下个 patch) 统一为：
- AC-NEW-V13-002 → `/data/attachments/{customer_id}/{attachment_id}/{filename}`
- 术语表 §LocalStorageBackend → 默认路径含 customer_id
- §3.4 状态机 §3.1 主流程 §3.6 BCP 等所有引用 path 的地方统一

### B-2. 422 状态码语义不统一（中优先级，需明确分层）

**问题描述**：
- §4.1 FR-SVR-001 验收："事务+文件不一致返回 422"
- §10.1 AC-NEW-V13-009："事务 FAIL 返回 422"
- §10.4 L2 契约测试："5 文件成功 + 1 失败 → 422"

3 处都用 422，但**"事务+文件不一致"和"5 文件成功 + 1 失败"语义边界模糊**：
- "事务+文件不一致"可能是 MD5 不匹配（业务校验失败）→ 422
- "5 文件成功 + 1 失败"是部分落地 + 部分失败（Multipart 异常）→ 也 422
- 两者在事务层都算 FAIL，但根因不同

**影响**：客户端收到 422 时无法判断是 MD5 不匹配（重传文件）还是 5/6 失败（重传整个事务）。

**修复建议**：分层 422 + body code：
```
HTTP/1.1 422 Unprocessable Entity
{
  "code": 0,
  "error": {
    "type": "MULTIPART_PARTIAL_FAIL",  // 或 MD5_MISMATCH / FILE_MISSING
    "message": "5 of 6 files uploaded, transaction failed",
    "details": {
      "uploaded": [ATT-1, ATT-2, ATT-3, ATT-4, ATT-5],
      "failed": [ATT-6],
      "cleanup_status": "is_orphan=true, GC in 24h"
    }
  }
}
```

### B-3. §3.1 主流程图与 §5.4 数据流图不完全一致（低优先级）

**问题描述**：
- §3.1 主流程图（line 234 起）显示"状态: ADB_CONNECTING → ... → DOWNLOADING → READY → RUNNING"
- §5.4 存储数据流图（V1.3.1 新增，line 1100+）显示完整文件流，但**没有体现 ADB_CONNECTING 状态**
- 两图都正确，但**未交叉引用**，读者需要在脑中合并

**影响**：实施团队需自行关联两个图。

**修复建议**：§5.4 末尾加一句"完整状态机见 §3.4"，§3.1 末尾加一句"完整文件流见 §5.4"。

### B-4. §7.10 USB 反向网络未声明 Android 版本兼容性（中优先级）

**问题描述**：
- §7.10 主推方案选 USB 反向网络（Airtest 框架原生）
- §2.1 AS-004："所有 Android 设备已开启 USB 调试和开发者模式"（V1.1）
- 但 **`adb reverse` 命令在 Android 版本间的稳定性**未在文档中声明

**影响**：如果生产环境发现某些 Android 10 设备 adb reverse 异常，需要切到站点 VPN fallback，但文档没说明切换条件。

**修复建议**：在 §7.10 末尾加"兼容性验证清单"：
```
- [ ] 测试设备 Android 10/11/12/13 各 1 台验证 adb reverse 行为
- [ ] 验证 USB 2.0 vs USB 3.0 速率（决定 8MB 平均文件下载耗时）
- [ ] 如发现 Android 10 部分型号 adb reverse 异常，切 §7.10 备选方案
```
